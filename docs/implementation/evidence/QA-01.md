# QA-01 — First public vertical evidence

## Цель и границы

Доказать первый browser-to-data vertical на утверждённом локальном `DATA-02` corpus: Home, News list и News detail получают данные через реальный API, а loading/empty/error состояния различимы.

- Проверялись только desktop public Home/News и необходимые API/media requests.
- Admin, полный mobile matrix, production content, mutations, retry UX и последующие `M2` задачи не проверялись.
- Production DB/Blob не читались и не изменялись.
- Коммит и новая ветка не создавались.

## Исходное состояние

- Зависимости `BASE-04` и `DATA-02` имели статус `done`; `QA-01` была `planned`.
- Worktree до задачи был чист.
- Home/News показывали fixture в happy path, но network failure страницы News отображался как `Новин немає`: error и empty были неразличимы.
- News list создавал React warning об отсутствующем `key`, а Home slider с одной fixture news создавал Swiper loop warning.
- Frontend production build и TypeScript проходили. Full ESLint baseline: 6 errors и 20 warnings.

## Выполненные изменения

| Область | Изменение |
|---|---|
| `HomeContext.tsx` | Добавлены отдельные `loading/success/empty/error` статусы для schedule, news и promotion video; non-200 и nullable ответы классифицируются явно |

Изменены только семь frontend-файлов Home/News и документы закрытия `QA-01`. Shared request architecture, backend contracts, CSS, admin/mobile и package versions не менялись.

## Локальная test topology

- Одноразовый PostgreSQL 17 на localhost с 24 EF migrations и утверждённым `DATA_02_LOCAL_FIXTURE.sql`.
- Одноразовый Azurite Blob на localhost с public `storonnimv-photo` и `storonnimv-video` containers.
- API Development/Release на `127.0.0.1:63111` и Vite на `127.0.0.1:63112`, соединённые через `VITE_API_URL`.
- Fixture: одна news, один future schedule, один promotion video, один group social и связанные JPEG/MP4; admin records отсутствуют.
- Для deterministic loading/empty проверки использован временный localhost mock с задержкой 3 секунды и пустыми валидными ответами. Для error проверки API был контролируемо недоступен.

Credentials, connection strings, fixture bytes и runtime logs в Git не добавлялись.

## Невыполненные проверки и проблемы вне scope

- Full admin/mobile/production flows не запускались по явной границе `QA-01`.
- Автоматических frontend tests в package scripts нет; backend test assembly содержит 0 тестов. Их создание запланировано в `QA-02`/`QA-03`.
- Full ESLint сохраняет существующие 6 errors/20 warnings. Task-файлы не добавили errors; системное исправление относится к `QA-03`.
- Backend build сообщает существующие advisories для `SixLabors.ImageSharp` 3.1.6. Package upgrade не входит в `QA-01`.
- Retry UX для Home остаётся частью `FEAT-03`; `QA-01` реализовала только необходимую различимость состояний.
- `12_DATA_COPY_WORKFLOW.md` содержит pre-existing stale API startup-project example, тогда как канонический `11_MIGRATION_WORKFLOW.md` правильно использует Infrastructure. В рамках QA использована каноническая команда; unrelated doc не менялся.
- Fixture доказывает локальный flow, но не качество будущего production content. Реальный import остаётся `OPS-03`/`M5`.
